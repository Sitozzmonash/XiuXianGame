# 架构与工程约定

## 分层

```text
┌─────────────────────────────────────────────────────────────┐
│ UI（components/game/**）     只读 save、只调 action，不改存档  │
├─────────────────────────────────────────────────────────────┤
│ 状态（lib/game/state/store.ts）  Zustand + persist            │
│   · 唯一写入口：把引擎结果落盘、维护 updatedAt                 │
│   · 只持久化 save 字段（localStorage: fanchen-wendao-save）    │
├─────────────────────────────────────────────────────────────┤
│ 引擎（lib/game/engine/**）    纯函数，无 React / 无副作用      │
│   battle / loot / idle / breakthrough / story / realm        │
├─────────────────────────────────────────────────────────────┤
│ 配置（lib/game/config/**）    纯数据：地图/怪物/装备/法宝/...   │
├─────────────────────────────────────────────────────────────┤
│ 契约（lib/game/types.ts）     GameSave 与全部领域类型          │
└─────────────────────────────────────────────────────────────┘
        ▲                                     ▲
        │ 同构（前端直接 import）              │ HTTP JSON
        └──────────── server/（FastAPI）──────┘
              云存档只对 GameSave JSON 做原样存取 + 增幅审计，
              不解析业务字段（避免两端逻辑漂移）
```

硬规则：

1. **UI 不碰存档字段**：需要什么数据就从 store 选择器 / `viewModels.ts` 取，派生统计（战力、属性行、品质色）都在 viewModels 里算。
2. **引擎纯函数**：输入存档与随机源（`makeRng(seed)` 可复现），输出结果对象；不读全局、不写存档、不发请求。
3. **随机必须走注入的 rng**：掉落、词条、奇遇抽取都接收 `rand`，保证测试可复现。
4. **存档结构变更只改 types.ts + defaults.ts 的 `migrateSave`**：老存档由迁移函数升级，禁止在读取处做兼容判断。

## GameSave 契约

`lib/game/types.ts` 是前后端共同事实源。要点：

- 数值统一用数字：百分比词条存小数（`0.12` = 12%）。
- `updatedAt`：任何 `mutate()` 自动刷新（毫秒时间戳），云同步用它比较新旧。
- 剧情关键状态全在存档里：`story.flags / seenNodes / npcs / karma / pending / realmRun`，所以云存档天然覆盖剧情进度。
- 服务端只在 `player_saves.save_json`（JSONB）原样存取；换存档结构不需要动后端。

## 新增内容

**新怪物 / 关卡**：都在 `lib/game/config/maps.ts`。
怪物加进 `MONSTERS`（id 前缀 `mob_`，给出 `hpMul/atkMul/defMul/aspd` 与 `kind`，Boss 需 `bossMechanics` ≥ 2、`skills` ≥ 1，否则 `npm run verify` 不通过）；关卡在对应地图的 `stages` 里按 1~50 编排，第 5/10/…/50 关复用既有精英/Boss 模板即可，怪物数值由 `monsterStats()` 按关卡指数放大，**不要手写数值**。

**新剧情节点**：`lib/game/config/story/main_story.ts` 加 `StoryNode`（`stageRange` 用图内关卡号，`chapter` 用于章节门控防跨图泄漏），再到 `maps.ts` 对应地图底部的 `storyMounts` 挂载。选项 `effects` 只能引用真实存在的物品 id；若叙述性道具没有对应实物，在 `lib/game/config/storyItems.ts` 的映射表里登记——`scripts/verify` 会校验 0 个无效引用。

**新法宝 / 功法 / 灵兽**：`treasures.ts / techniques.ts / pets.ts` 数组追加即可，UI 的图鉴与掉落池自动收录；品质池按章节门控（`equipment.ts` 的 set 过滤逻辑）避免前期爆出终局装备。

**新音效**：`lib/game/audio.ts` 内以振荡器 + 包络合成，注册进 `SFX` 表后 `playSfx('名字')` 即可用。

## 数值模型（摘要）

```text
怪物:  stat = BASE_1 × GROWTH^(图内关卡-1) × 怪物图鉴倍率 × kindMul × 十年倍增
        BASE_1 = { hp:180, atk:30, def:16 }   GROWTH = { 1.033, 1.02, 1.02 }
        kindMul: 普通 1 / 精英 2.2 / Boss 3.2

玩家:  属性 = 基础值 × (1 + 序号^指数 × 0.5) × 装备/法宝/功法加成
        BASE = { HP:1800, ATK:150, DEF:70 }   指数 = { 1.35, 1.4, 1.15 }

伤害 = 攻击 × 技能倍率 × (1 - 防御/(防御+defenseConstant))
```

平衡改动后跑 `npm run verify`（含 `simulate()` 与实时战斗胜率偏差 < 5% 的一致性校验、200 关可通性、掉落保底、挂机封顶）与 `npm run verify:engines` 验证。

## 云存档数据流

```text
GameShell mount
  └─ bootstrapCloud()            lib/game/api/cloud.ts
       ├─ POST /auth/guest        device_id 幂等建档 → JWT 存 localStorage
       ├─ GET  /save              404→推送本地 / 本地是新档→采纳云端 / 否则按 updatedAt 取新（30s 容差）
       └─ 订阅 store：save 引用变化 → 标脏 → 15s 节流 POST /save
                                    409 → 整体采纳服务端存档；401 → 重登重试一次
                                    visibilitychange/pagehide → 补推
埋点：trackEvent() 入队 → 30s / 切后台批量 POST /analytics/events（失败回队，绝不影响游戏）
```

所有失败路径都静默降级为纯本地模式——云同步永远是「锦上添花」，不能成为可玩性的前提。

### 自检脚本已知红灯（2026-09-14 记录，5 项）

数值重平衡（commit 69474b0：敌人成长 1.055/1.045 → 1.033/1.02，修为产出 40·s^0.92 → 160·s^1.35）之后，乙方自检脚本有 5 项断言未同步标定。引擎机制本身经探针复核均正常（见下），属测试场景标定问题。

**`npm run verify:engines` 1 项**

- `[5] 第 1 关收益量级`：断言 `stageReward(1) === {25, 40}`；引擎现为 `28·s^0.95 / 160·s^1.35`，第 1 关 = 28/160（重平衡的既定值，PRD 未规定精确系数）。改断言字面量即可。

**`npm run verify` 4 项（5b. Boss 机制真实生效）**

根因：场景用 `saveAtPower(20, 0)`（20 关全套 0 强化装备）打 20 关 Boss，约 7s 击杀；而机制窗口在 8s（shield）/ 11s（burst）/ 14s（seal，`SEAL_FIRST_AT=14`）之后才开启，战斗在窗口到来前已结束，四项对照全部测不出差异：

- 封印：bare 与 sealed 同为 7.15s 结束，输出完全一致（76090 = 76090），少出手 0 次；
- 抗性：双方都在击杀时结束，总伤害 ≈ Boss 血量 + 溢出（69987 vs 70037），0.85 的元素减免被淹没；
- 护盾：40s 窗口内 Boss 早已死亡，双方剩余 HP 都是 0。

最小修法（探针已验证可转绿）：保留玩家侧 `saveAtPower(20, 0)`，把对照敌人换成高关（`enemyWith(100, ...)` 且 `globalStage = 100`），战斗持续到 24s 左右，四项断言全部成立：

- 封印：6 seed 少出手 13 次、封印窗口内出手 0 次、输出 133995 vs bare 152383；
- 抗性：火焰路线 162145 vs 173421（−6.5%），物理路线分毫不差 155628 = 155628；
- 护盾：剩余 HP 743835 vs 裸怪 656369。

顺带暴露一个数值观察：玩家以「同关装备、0 强化」打 Boss 约 7s 即结束，shield / burst / seal 这些 8s 之后的机制在实战胜负已分时大概率不触发。建议逻辑侧评估 Boss 血量/成长是否需要为「机制演出」留出时长。
